# Issue #98439 Design: Remove Redundant Task Optimistic Message Fields

## Problem

`buildOptimisticTaskReportAction()` in `src/libs/ReportUtils.ts` currently stores the task action message twice: once in `originalMessage.text` / `originalMessage.html`, and again in `message[0].text`.

The issue asks to remove the unused `text` and `html` fields from optimistic data. Keeping those extra fields makes the optimistic object shape wider than necessary and can interfere with typed `Onyx.connect()` refactors.

## Scope

Change only the optimistic task-action builder used for `TASK_COMPLETED`, `TASK_REOPENED`, and `TASK_CANCELLED`.

In `buildOptimisticTaskReportAction()`:

- Remove `text: message` from `originalMessage`.
- Remove `html: message` from `originalMessage`.
- Keep `taskReportID`, `type`, and `whisperedTo` unchanged.
- Keep `message[0].text` unchanged so the visible optimistic action text is preserved.

Target shape:

```ts
const originalMessage = {
    taskReportID,
    type: actionName,
    whisperedTo: [],
};
```

## Non-goals

- Do not remove `message[0].text` or `message[0].html` from report actions.
- Do not modify normal `ADD_COMMENT` optimistic builders.
- Do not add downstream selector filtering in `Onyx.connect()`.
- Do not refactor unrelated report-action code.

## Data Flow

A task complete/reopen/cancel operation calls `buildOptimisticTaskReportAction()`.

The builder returns an optimistic report action containing:

1. Task metadata in `originalMessage`.
2. Renderable action text in `message[0].text`.

After this change, rendering continues to consume the existing `message` payload while the redundant display fields are no longer created in `originalMessage`.

## Testing

Add or update focused unit coverage for the three supported task action names:

- `TASK_COMPLETED`
- `TASK_REOPENED`
- `TASK_CANCELLED`

Assertions should verify:

- `originalMessage` does not contain `text`.
- `originalMessage` does not contain `html`.
- `originalMessage.taskReportID`, `originalMessage.type`, and `originalMessage.whisperedTo` remain intact.
- `message[0].text` still contains the supplied task action message.

Run the smallest relevant unit-test target first, then the repository-required typecheck/lint/test checks before opening a PR.

## Risks and Mitigation

### Rendering regression

Risk: removing the wrong message fields could hide optimistic task action text.

Mitigation: only remove fields from `originalMessage`; preserve and explicitly test `message[0].text`.

### Scope creep

Risk: similar-looking `html` / `text` fields in other optimistic builders could lead to unrelated changes.

Mitigation: restrict implementation to `buildOptimisticTaskReportAction()` unless the issue owner explicitly requests broader scope.

## Acceptance Criteria

The change is complete when:

1. `buildOptimisticTaskReportAction()` no longer adds `text` or `html` to `originalMessage`.
2. Task complete/reopen/cancel optimistic actions still expose their visible text through `message[0].text`.
3. Targeted tests cover the resulting object shape.
4. Required repository checks pass.
5. No unrelated optimistic-action builders are changed.
